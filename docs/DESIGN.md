# Design Spec — PHILATELY × EDITORIAL CONTEMPORÂNEO

ระบบดีไซน์นี้ผสม 3 แหล่ง

| แหล่ง | หยิบอะไรมา |
|---|---|
| **การ์ดแต่งงานของบ่าวสาว** | สีทั้งหมด (สกัดจาก pixel จริง) |
| **PHILATELY — the stamp album** | วัสดุ: กระดาษครีม เงานุ่ม neumorphic และ **กรอบแสตมป์มีรอยปรุ** |
| **Editorial Contemporâneo** | ภาษา: serif display, label ตัวพิมพ์ใหญ่, mono metadata, grid ไม่สมมาตร |

ทุกค่าต้องตรงกับ CSS variable ใน `public/styles.css`

## 3. Stamp component (หัวใจของดีไซน์)

```
╭ ─ ─ ─ ─ ─ ─ ╮   ขอบปรุ = 4 radial-gradient mask, composited ด้วย intersect
│  ╭────────╮  │   รู r=3.4px ทุก 12px
│  │  รูป    │  │   เนื้อแสตมป์ #FFFFFF + padding 7px
│  ╰────────╯  │   เงา 2 ชั้น (Philately neumorphic)
│  ชื่อ · เวลา  │   caption mono .56rem บนป้ายขาว
╰ ─ ─ ─ ─ ─ ─ ╯
```

| กฎ | ค่า |
|---|---|
| เอียงสลับ | `[-1.2, 0.8, -0.6, 1.1, -0.9, 0.5]deg` ตาม index (deterministic) |
| hover | ตรงขึ้น + ยก 2px, 220ms ease-out |
| ใบเด่น | ทุกใบที่ `(index+1) % 7 === 0` → span 2×2 + ตราประทับทอง |
| ตราประทับ | วงกลม `--gold` + วันที่ `DD.MM.YY` เอียง −9° opacity .78 |
| มากกว่า 120 ใบ | `.grid.simple` → ตัด mask ออก เหลือการ์ดกระดาษ (คุม FPS) |

**ทำไมใช้ mask ไม่ใช้ border:** รอยปรุต้องเป็นรอยเว้าเข้าเนื้อแสตมป์ ไม่ใช่เส้นทับ
ถ้าเบราว์เซอร์ไม่รองรับ `mask` จะเห็นเป็นสี่เหลี่ยมมน — ยอมรับได้ ไม่พัง

### 3.1 กรอบ 7 แบบ (สลับอัตโนมัติ)

แอตทริบิวต์คลาส `v0…v6` มาจาก `idx % 7` ใน `renderTile()` (ใบเด่น 2×2 ใช้ `v0` เสมอ)
ทุกแบบ **เปลี่ยนแค่กรอบ** — พื้นที่รูป ตำแหน่งป้ายชื่อ และมุมเอียงคงเดิม อัลบั้มจึงยังอ่านเป็นชุดเดียว
ของตกแต่งทุกชิ้นเป็น `::after` ที่ `z-index: 2` และป้ายทั้งหมดยกขึ้นเป็น `z-index: 3`

| คลาส | ชื่อแบบ | ลักษณะ | mask |
|---|---|---|---|
| `v0` | perforated | ขอบปรุ 4 gradient + รู r 3.4px | ใช้ |
| `v1` | souvenir sheet | เส้นทองชั้นใน + ขอบกระดาษหนา 3px | ตัดออก |
| `v2` | corner ticks | ขีดทองรูป L 4 มุม (8 linear-gradient) | ตัดออก |
| `v3` | album mount | แถบชมพูด้านซ้าย 5px + ชมพูเข้มใต้ 3px (เหมือนสันอัลบั้ม) | ตัดออก |
| `v4` | airmail | ลายทางคอรัลเฉียง 45° บน–ล่าง ข้างละ 4px | ตัดออก |
| `v5` | coil stamp | มุมโค้ง 11px + เส้นทอง 1px + รูปโค้ง 7px | ตัดออก |

> `v6` (ตรายกเลิก) ถูกถอดออกตามคำสั่งเจ้าภาพ — เป็นสัญลักษณ์ที่สื่อความหมายอะไรไม่ได้

**สัดส่วนกรอบ:** ใช้สัดส่วนจริงของภาพ (แนวตั้ง 3:4, แนวนอน 4:3 หรือ 16:9, จัตุรัส 1:1) โดยอ่านจาก
`naturalWidth/Height` ของ thumbnail แล้วเขียนลง `--ar` — ภาพจึงไม่ถูกครอปเลย
(จำกัดช่วง 0.5–2.2 เพื่อไม่ให้ภาพพาโนรามากลายเป็นเส้นบาง) การ์ดกริดเป็น masonry (`columns`)

**ทำไม 6 แบบไม่เยอะเกินไป:** ตัวแปรทุกตัวอยู่บน grid เดียวกัน (`minmax(92px, 1fr)`) สีเดียวกัน
และน้ำหนักเส้นเบา — สิ่งที่ต่างคือ "กรอบ" ไม่ใช่ "สไตล์" จึงไม่กลายเป็นอัลบั้มกระจัดกระจาย

**ข้อควรระวัง:** `::after` บน `.tile` ถูก mask ของพ่อแม่ตัดด้วย (กรณี `v6`) จึงวางตราไว้ในกรอบ
ไม่ให้ล้นออกนอกขอบ ถ้าจะทำ variant ใหม่ ให้เริ่มจาก `inset: n` ค่าบวกเสมอ

### 3.2 กรอบที่ดาวน์โหลดได้ (canvas)

ใน lightbox มีแถบ swatch **7 ตัว** (ไม่ใส่กรอบ + v0…v5) วางไว้ **กลางแถบล่าง** — ชื่อแขกอยู่ซ้าย
ปุ่มดาวน์โหลดอยู่ขวา ค่าเริ่มต้นคือ **ไม่ใส่กรอบ** และ **กดดูตัวอย่างได้ทันที** ภาพในจอจะเปลี่ยนเป็น
ภาพที่ใส่กรอบแล้ว (blob URL) ก่อนกดดาวน์โหลดจริง

| เรื่อง | กติกา |
|---|---|
| ขนาดขอบ | `max(14px, ด้านสั้น × 5.5%)` รอบภาพ |
| ไฟล์ออก | PNG (เพื่อให้รูปรุโปร่งใสจริง) |
| รูปรุ (v0) | `destination-out` เจาะวงกลมคร่อมขอบกระดาษ **และเว้น margin รอบนอก = รัศมีรู** ไม่งั้นรูถูกตัดครึ่งด้วยขอบ canvas |
| แถบแอร์เมล (v4) | วาดสองแถบ (บน+ล่าง) แยก clip — เวอร์ชันแรกวาดรวม path เดียว ทำให้ขอบล่างว่าง |
| ZIP | ไม่ผ่าน canvas เลย — ส่งไฟล์จาก R2 ตรง ๆ ไม่มีกรอบ |
| วิดีโอ | ดาวน์โหลดเป็นไฟล์ต้นฉบับเสมอ (ใส่กรอบไม่ได้) |

**ทำไมไม่ใช้ CSS พิมพ์กรอบลงไฟล์:** CSS อยู่ในจอ ไม่เคยอยู่ในไฟล์ `toBlob()` จึงต้องวาดซ้ำด้วย
canvas — สีและสัดส่วนอ้างจาก token เดียวกัน (`#c0a062`, `#efc7c8`, `#c0554c`)

## 4. โครงหน้า

```
cover        THE WEDDING COLLECTION / ชื่อคู่ / 22.11.26 / ขีดจำกัดไฟล์
tabsBar      ถ่ายรูป · ภาพความทรงจำ   (เส้นใต้เลื่อนตาม active)
tab-shoot    ชื่อ + 4 ปุ่ม (ถ่ายรูป/เลือกจากคลัง/อัดวิดีโอ/วิดีโอจากคลัง) + ตรวจก่อนส่ง + คิว + footNote
tab-album    ภาพความทรงจำ · n รูป → ปุ่มเลือก/ดาวน์โหลด → stamp grid (7 กรอบสลับ) → โหลดเพิ่ม
```

- ระยะขอบ 20–22px, เนื้อหากว้างสุด 780px
- section gap 20–26px (แน่นกว่า Editorial เพราะเป็นแอป ไม่ใช่บทความ)
- **ไม่มี 3 คอลัมน์เท่ากัน** — hero stamp 2×2 ทำให้ grid ไม่สม่ำเสมอ

### 4.1 บล็อก "ตรวจก่อนส่ง" (review strip)

ขั้นตอนบังคับก่อนอัปโหลดทุกครั้ง — ไม่มีอะไรออกจากเครื่องจนกด "อัปโหลด"

| องค์ประกอบ | สเปก |
|---|---|
| การ์ด | `background: var(--paper-hi)`, `border: 1px solid var(--seal)`, `--shadow-soft` |
| ชื่อบล็อก | mono `.66rem` letter-spacing `.12em` uppercase สี `--ink-soft` (เหมือน "กำลังส่ง") |
| ตัวนับ | `n ไฟล์ · x.x MB` ชิดขวา บรรทัดเดียวกับชื่อ |
| ตารางรูป | `repeat(auto-fill, minmax(84px, 1fr))`, gap 9px, ช่องละ `aspect-ratio: 1` |
| ปุ่มลบ | วงกลม 22px `--seal-ink` ตัว ✕ สีขาว มุมบนซ้าย (≥3:1 กับขาว) |
| ป้ายขนาด | พื้นดำโปร่ง 62% ตัวอักษรขาว mono `.54rem` มุมล่างซ้าย |
| ปุ่มหลัก | `อัปโหลด (n)` เต็มความกว้างฝั่งขวา, disabled เมื่อ 0 |
| ลิงก์รอง | `ลบทั้งหมด` (ถามยืนยันเมื่อมากกว่า 1 ไฟล์) |
| คำอธิบาย | บรรทัด `.hint` ยืนยันว่า "ยังไม่มีอะไรถูกส่งจนกว่าจะกดอัปโหลด" |

**กติกาคอนทราสต์:** ตัวอักษรทุกตัวในบล็อกนี้อยู่บน `--paper-hi` (ขาว) เท่านั้น ห้ามวางบน `--wash`
เพราะ `--ink-soft` บนชมพูได้แค่ ~2.8:1 ไม่ผ่าน AA

## 5. สิ่งที่ห้ามทำ

- ห้ามใช้ emoji เป็นไอคอน — ใช้ inline SVG (Lucide style) เท่านั้น
- ห้ามใช้ `--gold` กับข้อความ
- ห้ามใช้ `--green` กับตัวเนื้อหา (contrast ไม่ผ่าน)
- ห้ามดำสนิท (`#000`) — ใช้ `--ink`
- ห้ามใช้ `h-screen` — ใช้ `100dvh`
- ห้ามใส่รอยปรุทุกใบเมื่อเกิน 120 ใบ
- ห้ามใช้ gradient หลายสีหรือ saturation สูง

### ที่มาของภาพและสิทธิ์

ภาพทั้ง 4 ชิ้น **สร้างด้วย AI** (Gemini / Google AI Pro ของเจ้าภาพ) ตาม prompt ใน `docs/art/PROMPTS.md`
ไม่ได้ตัดมาจากการ์ดเชิญ และไม่ได้ใช้ภาพ stock ที่มีลิขสิทธิ์
→ ใช้ได้บนเว็บนี้และใช้ซ้ำในงานอื่นของเจ้าภาพ

**ห้าม**: นำลวดลายจากการ์ดเชิญมาใช้บนเว็บ (สิทธิ์แบบ single-use ของดีไซเนอร์)
**ทางเลือกถ้าต้องการภาพใหม่**: USDA Pomological Watercolors / Biodiversity Heritage Library (public domain) หรือสร้างใหม่ด้วย prompt เดิม

### ทำไม ring ถึงเป็น SVG ไม่ใช่ AI

วงกลมที่ต้องมีใบไม้ระยะเท่ากันรอบวงเป็นสิ่งที่ diffusion model ทำได้แย่ (เบี้ยวทุกครั้ง) และที่ 62px รายละเอียดจะหาย
SVG ให้ความสมมาตรเป๊ะ, 1.1 KB, และเปลี่ยนสีได้ด้วยการแก้ `stroke` บรรทัดเดียว
