ทุกตัวเลขในไฟล์นี้มาจากการยิงจริงด้วย `scripts/capacity_test.py` ไม่ใช่การประมาณ
สภาพแวดล้อม: เครื่องทดสอบ 1 เครื่อง (Windows, อัปโหลดผ่านอินเทอร์เน็ตบ้าน) → Cloudflare edge → Workers → R2

```bash
python scripts/capacity_test.py --base <url> --mode upload --concurrency 3 10 25 --count 25 --kb 850
python scripts/capacity_test.py --base <url> --mode upload --concurrency 25 50 100 --count 100 --kb 5
python scripts/capacity_test.py --base <url> --mode view   --concurrency 25 50 --count 150
```

## 3. โควตาจริงเมื่อถึงวันงาน (คำนวณ)

| รายการ | ตัวเลข | เทียบโควตาฟรี |
|---|---|---|
| อัปโหลด 300 คน × 25 รูป = 7,500 รูป | 15,000 requests (รูป + thumb) | 15% ของ 100k/วัน |
| คลิป 100 คลิป | 200 requests | — |
| **เปิดดู**: 300 เครื่อง × 300 รูป = 90,000 ครั้ง | 90,000 requests | **90% ของ 100k/วัน** |
| R2 Class A (เขียน) | ~15,000/เดือน | 1.5% ของ 1M |
| R2 Class B (อ่าน) | ~90,000/เดือน | 0.9% ของ 10M |
| พื้นที่จัดเก็บ | 7,500 × 0.9 MB ≈ 6.8 GB + คลิป | เพดาน 10 GB |

> ⚠️ **จุดที่อันตรายที่สุดคือ "การดู" ไม่ใช่ "การอัปโหลด"** — ถ้าแขก 300 คนเปิดอัลบั้มคนละครั้ง
> ในวันเดียว จะใช้โควตา 100,000 request/วันเกือบหมด ถ้าเกิน Worker จะหยุดตอบจนถึง 00:00 UTC (07:00 น. ไทย)
> รูปที่ browser โหลดไปแล้วจะ cache 1 ปี (`immutable`) จึงไม่นับซ้ำ แต่ "ครั้งแรก" ของแต่ละเครื่องยังนับ

**ทางแก้ที่คุ้มที่สุด**: ผูก **custom domain ของ R2** แล้วตั้ง `PUBLIC_MEDIA_BASE`
→ รูปทุกใบเสิร์ฟจาก CDN ตรง **ไม่กิน Worker request เลย** เหลือแค่ API ไม่กี่พันครั้ง

## 4. ปัญหาที่เกิดได้ และอาการที่เห็น

| # | ปัญหา | อาการ | รับมือ |
|---|---|---|---|
| 1 | Worker ครบ 100k request/วัน | หน้าเว็บโหลดไม่ขึ้น / รูปไม่มา จนถึง 07:00 น. | ตั้ง `PUBLIC_MEDIA_BASE` (custom domain R2) — ลด load ราว 90% |
| 2 | R2 เกิน 10 GB | อัปโหลดไม่ผ่าน (เขียนไม่ได้) | จำกัด `MAX_VIDEO_MB` ลง หรืออัปเกรด R2 ($0.015/GB) |
| 3 | เน็ตในงานอ่อน | upload ค้าง ช้ามาก ต้อง retry | แอปมี retry 3 ครั้ง + ปุ่ม "ลองใหม่ทั้งหมด"; แนะนำแขกย้ายไปใกล้ router |
| 4 | **ไม่มี rate limit ฝั่งแอป** | ใครมีลิงก์+รหัสก็อัปไม่จำกัด (อาจถม 10 GB) | เปลี่ยน `EVENT_CODE` หลังงาน, หรือเพิ่มลิมิตต่อ IP (ต้อง KV/D1) |
| 5 | Cloudflare บล็อก client ที่ไม่ใช่ browser | 403 `error code: 1010` | กระทบแค่สคริปต์/Postman — ใส่ User-Agent ของเบราว์เซอร์ |
| 6 | รูปใหม่ยังไม่ขึ้นในลิสต์ทันที | เพื่อนเปิดแล้วยังไม่เห็น | R2 list มีดีเลย์ระดับวินาที — แอป refresh หลังอัปโหลดสำเร็จอยู่แล้ว |
| 7 | dev server (miniflare) อิ่มตัวที่ ~40 concurrent | เทสต์ local ช้า/หลุด | เป็นเรื่องปกติของ dev — อย่าใช้ตัวเลข local ตัดสิน production |

## 5. ข้อแนะนำก่อนวันงาน

1. **ถ้าทำได้ ทำอย่างเดียว**: ผูก custom domain ให้ R2 (`cdn.<โดเมน>`) แล้วตั้ง `PUBLIC_MEDIA_BASE` — นี่คือตัวเปลี่ยนเกมเรื่องโควตา
2. ลด `MAX_VIDEO_MB` จาก 80 → 40 ถ้ากลัวพื้นที่เต็ม (คลิป 60 วิที่แอปอัดให้ ≈ 19 MB อยู่แล้ว)
3. แขก 300 คน × 25 รูป = 6.8 GB — เผื่อไว้ ถ้ามีคลิปเยอะอาจต้องอัปเกรด R2
4. หลังงาน: เปลี่ยน `EVENT_CODE` หรือปล่อยให้ `EXPIRES_AT = 2026-12-22` ปิดเอง
