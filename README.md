# Wedding Album — อัลบั้มรูปงานแต่งจากมือถือแขก

แขกสแกน QR แล้วถ่ายรูปได้เลย รูปถูกย่อและส่งขึ้นคลาวด์อัตโนมัติ จากนั้นทุกคนในงานเปิดดูรวมกันได้
ทำงานบน **Cloudflare Workers + R2** ทั้งหมด อยู่ใน free tier และ **ไม่มีฐานข้อมูล**

**ลิงก์ที่ใช้จริง (deploy แล้ว 15 พ.ย. 2026):** <https://wedding-album.rj-wedding.workers.dev/?e=demo-code>

## ทำอะไรได้

| ฟีเจอร์ | รายละเอียด |
|---|---|
| ชื่อเว็บ + logo | title = **The Wedding Collection** · ตราดอกไม้ตัดพื้นหลัง (`/art/logo.webp`) เป็น favicon และตรากลางหน้า cover |
| ถ่ายจากมือถือ | กดปุ่มเดียวเปิดกล้อง ใช้ `<input capture>` ของเบราว์เซอร์ ไม่ต้องติดตั้งแอป |
| ตรวจก่อนส่ง | รูปที่เลือกทั้งหมดเข้าบล็อก "ตรวจก่อนส่ง" — ดูเต็มจอได้ ลบทีละรูปหรือลบทั้งหมดได้ ยังไม่มีอะไรถูกส่งจนกว่าจะกด "อัปโหลด (n)" |
| ย่อรูปอัตโนมัติ | ≤3 MB ส่งตามเดิม · 3–5 MB ย่อเป็น 2048px q0.85 · &gt;5 MB ย่อเป็น 1600px q0.80 |
| ไม่ทำให้ไฟล์ใหญ่ขึ้น | ถ้าผลลัพธ์หลังย่อใหญ่กว่าไฟล์เดิม ระบบเก็บไฟล์เดิมไว้ (กันบั๊กอัปสเกล) |
| คิวอัปโหลด | ส่งทีละไฟล์ 3 งานพร้อมกัน ลองใหม่ 3 ครั้ง แสดงเปอร์เซ็นต์จริง และลบแถวที่ยังไม่เริ่มส่งได้ |
| วิดีโอ | **อัดในหน้าเว็บ** (getUserMedia + MediaRecorder, สูงสุด 60 วิ, ได้ MP4/H.264 ถ้าเครื่องรองรับ) หรือแนบจากคลัง สูงสุด 80 MB · สร้างภาพปกอัตโนมัติ · เล่นใน lightbox |
| อัลบั้มรวม | ทุกคนที่มีลิงก์เห็นรูปทั้งหมด แบ่งหน้าโหลดทีละ ~300 รายการ |
| ดาวน์โหลด ZIP | ปุ่ม “ดาวน์โหลดภาพทั้งหมดในรูปแบบ .zip” — สร้าง ZIP แบบ stream ลงดิสก์ (ไม่กิน RAM) และ **ไม่มีกรอบฝังในไฟล์** ทุกไฟล์คือต้นฉบับ |
| ดาวน์โหลดรูปเดี่ยว | เปิดรูปใน lightbox แล้วเลือกกรอบได้ 7 แบบ หรือ “ไม่ใส่กรอบ” (ค่าเริ่มต้น) ระบบวาดกรอบลงภาพจริงเป็น PNG ความละเอียดเต็ม |
| หมดอายุ | ตั้ง `EXPIRES_AT` แล้วระบบจะตอบ 410 หลังเวลาที่กำหนด |
| ภาษาไทย | UI ไทยทั้งหมด ฟอนต์และชื่อไฟล์ภาษาไทยไม่เพี้ยน (UTF-8 flag ใน ZIP) |

## โครงสร้าง

```
wedding-album/
├── src/worker.js          API + media proxy (R2 binding, ไม่มี DB)
├── public/                หน้าเว็บ static (Pages/Assets)
│   ├── index.html
│   ├── app.js             กล้อง, ย่อรูป, คิว, gallery, lightbox
│   ├── zip.js             ZIP writer (store-only, streaming)
│   └── styles.css
├── scripts/               เครื่องมือทดสอบและ ops
├── docs/DEPLOY.md         คู่มือขึ้น production
└── wrangler.toml          ตั้งค่าอีเวนต์ + R2 binding
```

### ทำไมไม่มีฐานข้อมูล

อัลบั้มสร้างจาก `R2.list()` โดยตรง ตั้งชื่อไฟล์เป็น `m/<id>.jpg`, `m/<id>-t.jpg` (thumb),
`m/<id>.mp4`, `m/<id>-p.jpg` (poster) แล้วจับกลุ่มด้วย `<id>`
ชื่อแขกและเวลาถูกเก็บใน `customMetadata` ของ object
ผลคือไม่มี DB ให้ดูแล ไม่มี migration และไม่ต้องกังวลเรื่อง connection limit

## เริ่มใช้งานในเครื่อง

```bash
npm install
npm run dev          # http://127.0.0.1:8787/?e=demo-code
```

Wrangler จะจำลอง R2 ไว้ใน `.wrangler/state` (ลบโฟลเดอร์นี้ = ล้างรูปทั้งหมดในเครื่อง)

## ตั้งค่าอีเวนต์

แก้ใน `wrangler.toml` หัวข้อ `[vars]`

| ตัวแปร | ความหมาย |
|---|---|
| `EVENT_NAMES` | ชื่อคู่บ่าวสาว แสดงเป็นบรรทัดใหญ่กลางหน้า |
| `EVENT_TITLE` | ป้ายเล็กเหนือชื่อ (เช่น `Wedding Album`) |
| `EVENT_DATE` | วันที่ (ใช้แสดงผลเท่านั้น) |
| `EVENT_CODE` | รหัสห้อง ต่อท้ายลิงก์ด้วย `?e=รหัส` เว้นว่าง = เปิดสาธารณะ |
| `EXPIRES_AT` | เวลาหมดอายุแบบ ISO เช่น `2026-12-19T23:59:59+07:00` |
| `MAX_PHOTO_MB` / `MAX_VIDEO_MB` | เพดานขนาดไฟล์ |
| `PUBLIC_MEDIA_BASE` | โดเมน CDN ของ R2 (ดู `docs/DEPLOY.md`) — ไม่ตั้ง thìรูปวิ่งผ่าน Worker |

## ทดสอบ

เปิด `npm run dev` ค้างไว้ก่อน แล้วรันทีละตัว

```bash
npm run demo          # ใส่รูปตัวอย่าง 8 รูป (สำหรับดูดีไซน์)
npm run test:smoke    # API: config / upload / list / media / auth
npm run test:zip      # ZIP writer + ตรวจด้วย zipfile ของ Python
npm run test:prep     # อัปรูปจริง 3200x2400 แล้ววัดว่าลดขนาดจริง
npm run test:ui       # Playwright: กล้อง→อัป→อัลบั้ม→lightbox→วิดีโอ→ZIP
npm run test:load     # ยิงพร้อมกัน 40 เครื่อง x 3 รูป
npm run test:thai     # ตรวจ mojibake ในไฟล์ภาษาไทย
npm run shot -- docs/screenshots/live.png "http://127.0.0.1:8787/?e=demo-code" shoot
```

ผลการทดสอบล่าสุดในเครื่องนี้

| ชุดทดสอบ | ผล |
|---|---|
| smoke | 12/12 |
| zip | ผ่าน (archive valid, CRC ok, ชื่อไทยไม่เพี้ยน) |
| prep | 4.74 MB → 0.73 MB (15.4%) |
| ui | 10/10 ไม่มี console error |
| load | 240 คำขอ, 0 ล้มเหลว, 120 MB ใน 11.1 วินาที |

## ความจุโดยประมาณ

สมมติแขกแต่ละคนถ่าย 25 รูป และรูปถูกย่อเหลือ ~1 MB

| จำนวนแขก | จำนวนรูป | พื้นที่ |
|---|---|---|
| 150 | 3,750 | ~3.8 GB |
| 300 | 7,500 | ~7.5 GB |
| 400 | 10,000 | ~10 GB (เต็มโควตาฟรีพอดี) |

R2 ให้ 10 GB ฟรี และ egress ฟรีไม่จำกัด ส่วนที่เกินคิด $0.015/GB/เดือน
(300 แขกยังอยู่ในโควตา, 500 แขกจ่ายเพิ่มประมาณ $0.04)

## ข้อจำกัดที่ควรรู้

- **ต้องเป็น HTTPS** เบราว์เซอร์มือถือจะไม่ยอมเปิดกล้องบน HTTP
- ลิงก์เดียวแปลว่าทุกคนเห็นทุกรูป ไม่มีการแยกสิทธิ์รายคน
- ZIP ไม่รองรับ ZIP64 จึงจำกัดที่ 4 GB ต่อไฟล์ (ถ้าเกินให้เลือกเป็นชุดย่อย)
- รองรับไม่เกิน 65,535 ไฟล์ต่อ ZIP
- ถ้าไม่ตั้ง `PUBLIC_MEDIA_BASE` รูปทุกใบจะวิ่งผ่าน Worker (นับเป็น request)
